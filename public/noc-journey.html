Section 0 — Who Can Raise a Resignation & What Each Party Sees
Three initiators · Same FSM flow · Employee always sees it · Withdrawal rules enforced server-side
👤
Employee — Self Service
HRMS Portal / My Resignation
Opens /exit/resignation in their portal. Fills reason, notice date, F&F preference. Server forcibly overwrites the employeeId body field with their own ID — they cannot raise for anyone else even by manipulating the request body. Completely safe.
initiated_by = 'employee'Own record only
🧑‍💼
Manager — On Behalf
Exit Command Center
Manager with manager role can raise an exit for any team member by supplying their employeeId. Server sets initiated_by = 'manager' from the caller's role — body cannot override. Can cover absences, forced exits, or resignation capture during appraisals.
initiated_by = 'manager'Any team member
👩‍💼
HR / Admin — Involuntary
Exit Command Center
HR handles involuntary exits — absconding, abandonment, termination. Sets exit_type = 'absconding', records absconding_since (the last day employee actually worked). Server sets initiated_by = 'hr' from role. LWD = absconding_since directly — no grace days.
initiated_by = 'hr'Any employee
👁️
Employee Always Sees Their Resignation — Regardless of Who Raised It
GET /api/exit/resignation/my → WHERE employee_id = logged-in user's employee id — returns ALL records on their account
✅ What Employee Sees
📊
Current status with full timeline (submitted → manager_review → accepted…)
🏷️
Who raised it — initiated_by field shows 'employee' / 'manager' / 'hr'
📅
Confirmed last working day once set by HR
🤝
Retention offers from HR — can respond: accept / decline with remarks
🕵️
Full audit trail — every status change with actor name and timestamp
⚡ What Employee Can / Cannot Do
✅
Withdraw their own resignation — ONLY while status = submitted. Backend checks employee_id + status gate.
✅
Respond to retention offers — accept or decline with remarks, visible to HR and manager.
🚫
Cannot withdraw HR-raised absconding/involuntary exit — only HR/Admin can revoke it.
🚫
Cannot withdraw after manager accepts — locked for employee once past submitted status.
🚫
Cannot bypass clearance tasks, skip NOC chain, or approve their own F&F.
✅ Same FSM flow regardless of who raises the resignation
submitted→ manager_review→ accepted→ notice_serving *→ clearance_pending→ fnf_pending→ closed / exited
* notice_serving is skipped for absconding/involuntary exits — goes directly from accepted → clearance_pending

Finance Asset Gate
Every item with is_mandatory_for_finance = 1 must have status = 'returned' OR waived_at IS NOT NULL. Finance Accept button is disabled in UI while gate is open. SLA reminder worker also excludes Finance from overdue alerts while structurally blocked.

Decline Path — Any Tier
Any signatory can Decline with a mandatory remark. Status → declined. Chain halts. HR gets high-priority inbox alert. HR resolves the issue and reopens the case — declined stage resets to pending and chain continues from that point.

Section 4 — 3 Gates Before "Exited" & Final Outcomes
ALL three must pass (checked in finalExitBlockers()) · Any one open gate blocks the exited transition
📋
Gate 1 — Clearance Tasks
0 open tasks in exit_clearance_task. Every task must be status = cleared or waived before transition to exited is allowed.
💰
Gate 2 — F&F Approved
full_final_calculation must exist, status = "approved" or "paid", and is_ff_provisional must be 0 (not provisional).
🔐
Gate 3 — NOC Completed
If NOC is required (inactive employee + open salary), noc_case.status must be "completed" before exited transition is allowed.
📜
NOC Certificate Generated
Digital 8-signature certificate auto-generated. All signatories listed with name, role, timestamp, remarks. Printable from clearance workspace.
💸
Salary & F&F Released
Payroll salary gate lifts. F&F settled per chosen route: current payroll / 45 days / both. Payroll Head and HR notified via Work Inbox.
🗃️
Employee Fully Exited
Status → exited / closed. Experience letter, relieving letter generated. Employee account deactivated. All inbox tasks auto-resolved.

Section 5 — System Automations
Zero manual triggers required — everything fires on schedule or on event
⏰
Daily 8 AM — NOC Case Auto-Creation
Scans exit_requests where LWD ≤ today, status not terminal, no existing NOC case. Auto-opens case, mints invite link, emails employee, creates HR Work Inbox item (high priority). 7-day lookback for missed LWDs. openCase() is idempotent — safe to re-run daily.
📨
Event-Driven — Stage Unlock Notifications
Every accepted stage immediately notifies the next stage holder (email + Work Inbox). HR accepting Tier 4 notifies all 4 Tier-5 holders simultaneously. Notifications are deduplicated — no double-firing even on retry.
🔔
Hourly — SLA Breach Reminders
noc-sla-reminder worker sweeps every hour. Stages past 48h SLA get up to 3 reminders (24h apart). Reminders #2 and #3 copy Branch Head. Finance excluded while asset gate is structurally blocked. Max 40 reminders per sweep.
🎯
On Completion — Inbox Cleanup + Gate Lift
When last required stage is signed: all NOC inbox items auto-resolved, salary release gate lifts, HR and Payroll Head receive completion notification with F&F route. Case permanently marked completed.
